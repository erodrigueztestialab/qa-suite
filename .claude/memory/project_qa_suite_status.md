**Chatbot QA (banco de conocimiento) — working against the REAL folder as of 2026-08-19, with an important architecture change from the original PoC:**
- Original PoC design gave Claude CLI tool access (`Read`/`Grep`/`Glob`) to `KNOWLEDGE_DIR` via `--add-dir` + `--allowedTools`, generalized through `callClaude()`'s `opts.addDir`/`opts.allowedTools`/`opts.systemPrompt`. This worked fine against the small synthetic `knowledge/` folder but **failed against the real folder** (`C:\Esteban\1.TESTIALAB-TODO\Capacitaciones`) with Claude reporting "no tengo permiso para acceder a esa carpeta".
- Root cause (confirmed via `stream-json` output's `permission_denials` field): when `proxy.js` (a Node child_process) spawns the `claude`/`claude.cmd` CLI on Windows, the Glob/Grep/Read tool calls against an `--add-dir`-granted folder get silently denied by the CLI's own permission checker — even with `--permission-mode bypassPermissions` — specifically when the parent process is a spawned Node child. The exact same CLI invocation (identical args, identical system prompt) run directly from an interactive shell succeeds every time; only the Node-spawned path fails. This is **not** a `shell:true`/argument-escaping issue (installing/switching to `cross-spawn` did not fix it — that avenue was a dead end, ruled out via an isolated reproduction script that reproduced the same `permission_denials` even with clean, correctly-escaped args).
- **Fix applied:** stopped relying on Claude's own filesystem tools entirely for this endpoint. `proxy.js` now has `readKnowledgeTextFiles(dir)` (plain Node `fs`, recursive) which reads every `.txt` in `KNOWLEDGE_DIR` and embeds the full content directly into the prompt (`buildChatQaPrompt`), same technique the app already uses elsewhere for plain-text documents. No `--add-dir`/`allowedTools` passed for this call anymore. The real knowledge base is tiny (~130KB across 6 files today), so full-embed is simple and reliable — reassess only if the folder grows to the point of blowing the prompt budget.
- `ensureKnowledgeTextCache()` (docx→txt extraction via mammoth) is unchanged and still runs before every request.
- `cross-spawn` is now a dependency of the project (`package.json`) and `spawnClaudeOnce()` in `proxy.js` uses it instead of raw `spawn(..., {shell:true})` for the Claude CLI call — kept even though it wasn't the fix for this bug, since it's still a strictly safer replacement for Windows `.cmd` spawning than unescaped `shell:true` (Node's own `DEP0190` deprecation).
- **Verified end-to-end against the real folder**: 3 real curl calls (direct question with correct file citation, a question with no matching content correctly answered "not found" without hallucinating, and a multi-turn follow-up correctly using conversation history to switch between the two real requirements RQ-5556/RQ-5550) + 1 full real-browser UI test (typed question → real Claude call → rendered bubble with correct citation `RQ-5556 - Mejoramiento lectura de contenedores WHS\REQ-Mejoramiento lectura de contenedores WHS.txt`).
